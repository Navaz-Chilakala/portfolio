Inside the AI Diagnostics Agent

A security gateway keeps sensitive identifiers out of the LLM.

  1. 1

    An engineer asks a question or runs a slash command.

  2. 2

    The agent loads the matching skill and runbook, locks to one cluster and anchors time from the OS clock.

  3. 3

    MCP tool calls pass through the gateway: allowlist, downstream call, sanitization, audit.

  4. 4

    PromQL metrics, Elasticsearch/Kibana logs and Kubernetes state are correlated into a templated HTML/SVG root-cause report.

The custom Python MCP gateway redacts customer and device identifiers, phone numbers, JWTs and secrets before they reach the model, using session-scoped HMAC-SHA256 tokens, fail-closed tool allowlists and a hash-only audit log. Read-only access is enforced at multiple layers and each cluster stays isolated.

Operations knowledge lives as prompt-as-code (slash commands, skills, runbooks, report templates) with live metric-existence checks and evidence-only rules that stop fabricated findings.

Also: Elasticsearch/Kibana, Grafana/Loki, MariaDB, MongoDB, SQLite, Linux (SSH, systemd), HTML/SVG

    The in-browser demo runs the full pipeline with no backend: it decodes call signaling (SIP), data-session control (PFCP), core service APIs (HTTP/2 SBI) and voice media (RTP), builds per-flow features, classifies each flow with a Random Forest, retrieves matching 3GPP passages (TS 23.501, 29.244, 29.500, 24.229, 33.501) and explains the root cause, with a chat box for follow-up questions.
